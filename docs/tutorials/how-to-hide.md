# 如何发布一篇私密文章

这个站点支持「私密文章」：不出现在任何导航和列表里，正文构建时加密，别人只有知道**访问编号**或**标题**（通过搜索找到文章）并输入访问码才能阅读；而你作为站长，用主访问码可以看到并解锁全部私密内容。

## 快速上手：三个命令

在项目根目录（`package.json` 所在目录）打开终端：

```bash
npm run src:new "文章标题"   # 新建一篇私密文章，自动分配访问编号
npm run dev                  # 本地写作、预览（私密文章本地直接可见）
npm run src:lock             # 推送前加密源文件，防止公开仓库泄露明文
```

## 完整流程

### 第一步：新建文章

```bash
npm run src:new "给某位朋友的笔记"
```

命令会：在 `docs/private/posts/` 下创建 Markdown 文件、生成一个随机访问编号（如 `4DF158F1`）、把编号登记到 `docs/.vitepress/private-secrets.json`。终端会打印出文件路径和编号，**把编号记好**。

### 第二步：写作与预览

直接编辑新建的 `.md` 文件，运行 `npm run dev` 预览。本地预览时你能看到所有私密文章（侧边栏也会出现「私密区」分组），不需要输入任何码。

私密文章请使用标准 Markdown 语法；图片请放到 `docs/public/` 并用绝对路径引用（如 `/img/xxx.png`），或直接用外链图片。

### 第三步：加密源文件

**推送到 GitHub 之前，务必运行：**

```bash
npm run src:lock
```

它会把明文正文加密成 `enc` 字段写回文件。因为 GitHub Pages 要求仓库公开，如果不加密，任何人打开你的仓库就能直接读到私密文章明文。加密后的文件可以放心提交。

之后想再编辑这篇文章，先运行 `npm run src:unlock` 解密回明文，改完再 `src:lock`。

### 第四步：提交发布

```bash
git add .
git commit -m "新增私密文章"
git push
```

::: warning 重要
GitHub Actions 构建时也需要密钥，否则私密文章会以「无法解锁」的状态发布。请在仓库 Settings → Secrets and variables → Actions 里新建一个名为 `PRIVATE_SECRETS` 的 secret，内容就是本地 `docs/.vitepress/private-secrets.json` 文件的完整 JSON 文本。
:::

## 怎么把私密文章分享给别人

- **告诉编号**：对方在网站搜索框输入编号（如 `4DF158F1`）即可找到文章，输入同样的编号解锁阅读。搜索标题也可以找到文章。
- **发送直链**：在文章链接后加上 `?key=编号`，例如 `https://你的域名/private/posts/note-20260804-a1b2?key=4DF158F1`，对方打开自动解锁。

## 站长入口：私密区

访问 [/private/](/private/) 页面（建议加入书签），输入主访问码后可以查看全站所有私密文章的列表、复制编号、逐篇解锁。主访问码保存在 `private-secrets.json` 的 `masterCode` 字段，想更换就修改它并重新部署（已用旧码解锁过的浏览器需要重新输入）。

## 安全须知

- 私密功能属于「不展示 + 访问码」级别的保护：足以挡住随意浏览的访客，但不是服务器级别的权限控制。
- 正文在构建时用 AES-256-GCM 加密，网页和 JS 里没有明文；但请理解：任何发布到互联网的内容，理论上都存在被破解的可能。
- 访问编号建议保持随机、不要起有意义的名字；私密文件本身（加密后）可以安全地放在公开仓库里。
- 真正机密的信息请不要放在任何网站上。
